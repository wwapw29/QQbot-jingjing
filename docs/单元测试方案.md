# QQBot 单元测试方案（第一层：确定性逻辑）

> 目标：给静静里"输入固定 → 输出固定"的纯逻辑函数补上断言保护，让改代码/改提示词不再裸奔。
> 范围：**只测确定性代码**；LLM 行为质量属于「评测集（第三层）」，不在本文档范围。
> 状态：待实施 ｜ 日期：2026-08-14

---

## 1. 为什么先做这一层

- 静静目前没有任何自动化测试，解析逻辑（回复提取、消息段解析、合并拼接）一旦改坏，只能靠手动在 QQ 里试。
- 这些函数是**确定性纯逻辑**：同样的输入永远得到同样的输出，写断言 100% 可复现、可自动跑。
- 成本最低（半天工作量）、收益最稳，是所有 agent 项目唯一能完全自动化的测试层。

## 4. 前置小重构：把 private 纯函数抽成公共类

当前这些解析函数埋在 `EventDispatcher` 里（private static），测试项目无法直接访问。**先搬函数、再写测试**，搬移不改变任何行为：

### 4.1 新建 `src/QQBot/Core/Chat/ReplyRoundParser.cs`

把以下方法从 EventDispatcher 搬进来（改成 public static）：

```csharp
namespace QQBot.Core.Chat;

/// <summary>回复轮次 JSON 解析（纯函数，可单测）：{reply, more} 结构容错提取</summary>
public static class ReplyRoundParser
{
    /// <summary>先提取最外层 JSON 对象再解析；解析失败返回 false（格式无效）</summary>
    public static bool TryParseReplyRound(string content, out string text, out bool more);

    /// <summary>解析纯 JSON 对象文本，提取 reply/more；失败返回 false</summary>
    public static bool TryParseReplyJson(string json, out string text, out bool more);

    /// <summary>从任意文本中抠出最外层 {...} JSON 对象；无则 null</summary>
    public static string? ExtractJsonObject(string s);

    /// <summary>宽松提取正文（格式不合格时的兜底）</summary>
    public static string ExtractLooseReply(string content);

    /// <summary>格式垃圾判定（JSON 残骸 / 标记残留等）</summary>
    public static bool IsFormatJunk(string? content);
}
```

### 4.2 新建 `src/QQBot/Core/Dispatcher/MessageText.cs`

把消息段解析组搬进来：

```csharp
namespace QQBot.Core.Dispatcher;

/// <summary>OneBot 消息段 → 文本/结构 的纯解析（可单测）</summary>
public static class MessageText
{
    public static string GetPlainText(JsonArray? segments);                  // 只取 text 段
    public static long ExtractQuoteId(JsonArray? segments);                  // reply 段 id
    public static List<string>? ExtractImageUrls(JsonArray? segments);       // image 段 url
    public static bool HasForwardSegment(JsonArray? segments);               // 是否含转发段
    public static string? ExtractForwardId(JsonObject? data);                // forward 段 id（兼容字符串/数字）
    public static long[] ExtractMentionedQqs(JsonArray? segments);           // 提及的 QQ 列表
}
```

### 4.3 改 EventDispatcher

- 删除搬走的私有方法，调用处改为 `ReplyRoundParser.xxx(...)` / `MessageText.xxx(...)`。
- **验证方式**：搬完 `dotnet build` 0 错误 + 手动跑一两条对话确认行为不变，再开始写测试。

## 5. 用例设计示例（直接可抄）

### 5.1 ReplyExtractorTests.cs

```csharp
using QQBot.Core.Chat;
using QQBot.Core.Options;
using Xunit;

namespace QQBot.Tests;

public class ReplyExtractorTests
{
    [Fact]
    public void Delimiter策略_截取最后一个分隔符之后()
    {
        var result = new ChatResult(
            "思考过程……\n```END_REASONING```\n{\"reply\":\"你好呀\",\"more\":false}",
            null);
        var opt = new ReplyExtractionOptions { Strategy = "delimiter", Delimiter = "```END_REASONING```" };

        var text = ReplyExtractor.Extract(result, opt);

        Assert.Contains("\"reply\":\"你好呀\"", text);
    }

    [Fact]
    public void 无分隔符_返回原文()
    {
        var result = new ChatResult("纯文本回复", null);
        var opt = new ReplyExtractionOptions { Strategy = "delimiter", Delimiter = "```END_REASONING```" };

        Assert.Equal("纯文本回复", ReplyExtractor.Extract(result, opt));
    }

    [Fact]
    public void 空内容_返回空串()
    {
        var result = new ChatResult(null, null);
        Assert.Equal("", ReplyExtractor.Extract(result, new ReplyExtractionOptions()));
    }
}
```

### 5.2 ReplyRoundParserTests.cs

```csharp
[Theory]
[InlineData("{\"reply\":\"hi\",\"more\":false}", "hi", false)]          // 干净 JSON
[InlineData("前缀{\"reply\":\"x\",\"more\":true}后缀", "x", true)]       // 容忍杂质
[InlineData("不是json", "", false)]                                      // 无效输入
[InlineData("", "", false)]                                              // 空输入
public void TryParseReplyRound_常见输入(string input, string expectText, bool expectMore)
{
    var ok = ReplyRoundParser.TryParseReplyRound(input, out var text, out var more);
    Assert.Equal(expectText.Length > 0, ok);
    Assert.Equal(expectText, text);
    Assert.Equal(expectMore, more);
}
```

### 5.3 SegmentParserTests.cs

```csharp
[Fact]
public void GetPlainText_只取text段_忽略at段()
{
    var segs = new JsonArray
    {
        new JsonObject { ["type"] = "at", ["data"] = new JsonObject { ["qq"] = "10001" } },
        new JsonObject { ["type"] = "text", ["data"] = new JsonObject { ["text"] = "你好" } },

[Theory]
[InlineData("12345", "12345")]   // 字符串 id
[InlineData("54321", "54321")]   // 数字 id（序列化后为字符串）

{

{
```

## 7. 接入日常流程（红线）

1. **改 EventDispatcher / ReplyExtractor / 消息解析相关代码** → 顺手跑 `dotnet test`，红了先修再交付。
2. **新增解析逻辑** → 同步补用例（不写测试的解析改动视为未完成）。
3. 与第三层评测互补：**单测保"不炸"，评测保"不变笨"**——单测负责结构正确，评测负责 LLM 行为不退步。

## 8. 注意事项

- **ChatResult / ChatMessage 构造**：测试里需要引用 `QQBot.Core.Chat` 命名空间；`ChatResult(content, reasoningContent)` 两个参数。
- **JSON 断言**：比较整段 JSON 时注意键顺序（JsonNode 序列化顺序不保证），优先断言 `Contains` 关键片段，或 `JsonNode.DeepEquals`。
- **中文与转义**：C# 11+ 用原始字符串字面量 `"""..."""` 写 JSON 用例更清晰（当前项目 net10.0 支持）。
- **JsonNode 不能有双父节点**：构造含重复节点的数组会抛异常（`The node already has a parent`），复用测试数据时注意 `DeepClone()`。
- **不要测**：LLM 行为、真实网络（get_forward_msg 等 API 调用）——那是集成/评测层的事。
