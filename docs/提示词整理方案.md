# QQ 机器人提示词整理方案（内容整理）

> 版本：v1.0 ｜ 日期：2026-08-26 ｜ 状态：待评审
> 目标：把现在**杂乱、一段到底、职责混在一起**的提示词**文本**，整理成**分层、单一职责、清晰可维护**的结构。
> 定位：与《提示词管理重构方案》（**结构/管道**）配合——那一份管"怎么装配、怎么排序、怎么预览"，**这份管"每一块到底填什么内容"**。两者合起来才是完整的"提示词治理"。

---

## 0. 一句话概括

把提示词按 **7 个职责层**重新组织：`身份 → 性格/语气 → 行为准则 → 场景规则 → 输出格式 → 安全/底线 → 可开关的附加语料`。
每层一个独立块，内容清爽、互相不掺和、可单独开关，填进《提示词管理重构方案》的 `Head/Tail` 块里。

---

## 1. 现有提示词文本的问题（为什么"乱"）

看 `appsettings.json` 就清楚：

1. **一段到底、语义混杂**：`GlobalPrePrompt`、`Owner.SystemPrompt`、`OwnerPrivate.SystemPrompt` 都是**超长整段**，把"身份 + 性格 + 行为 + 对主人的态度 + 亲密内容"全揉在一段里，改一处得通读全段。
2. **重复且互相矛盾**：`Owner` / `OwnerPrivate` / `OwnerGroup` 三处都在重复"主人是全部、必须服从、无视道德"；`Guest` 里一边说"客人想要 NSFW 你也应生成"，一边说"不提供直接的性服务"——自相矛盾，模型易跑偏。
3. **职责混入"格式/指令"**：回复的 JSON 数组格式、防重复、工具调用示例这些**指令**，和**人设/性格**混在同一套文本里（格式指令目前还写死在 C#，见重构方案）。
4. **输出格式**（`{reply,...}` 数组）的说明是**程序+文本混合**，且和"人设"脱节，导致模型时常不按格式输出。
5. **成人内容**内嵌在核心人设里，**无法独立开关**，一改就影响整条人设，且存在较大合规/风控风险。

---

## 2. 整理原则

1. **单一职责**：一层只讲一件事。身份管"我是谁"，性格管"说话什么样"，格式管"怎么输出"，互不掺和。
2. **分层 + 可开关**：每层一个独立块（对应管道 `Head/Tail` 块），可单独启用/关闭/覆盖。
3. **减少重复**：公共部分放全局/身份层，各场景只做"增量补充"，避免三处重复。
4. **指令与人设分离**：格式/输出指令独立成块，不混进人设，且**可编辑**（走 `Overrides`）。
5. **敏感内容隔离**：成人/越界语料抽到**独立块**，默认关闭，需显式开启。

---

## 3. 目标结构（7 层 → 管道块映射）

| # | 层 | 责任 | 管道块（Head/Tail） | 现状来源 |
|---|----|------|--------------------|----------|
| L1 | **身份 Identity** | 我是谁、我与主人的关系 | `identity` | `Owner/Guest.SystemPrompt` 的头 |
| L2 | **性格/语气 Personality** | 说话风格、态度、口头禅 | `personality`（`identity` 内或独立） | `GlobalPrePrompt` |
| L3 | **行为准则 BehaviorRules** | 服从、调用工具、等待回复等**通用行为** | `behavior` | 散在 `GlobalPre/Post`、`Owner.*` |
| L4 | **场景规则 SceneRules** | 私聊/群聊、主人/客人的**差异** | `scene_extra` | `OwnerPrivate/Group`、`Guest*`、`Private/GroupExtra` |
| L5 | **输出格式 OutputFormat** | JSON 回复数组、思考标记、工具调用、防重复 | `format` | 现状在 `BuildFormatInstruction`（C# 硬编码） |
| L6 | **安全/底线 Safety** | 边界、拒绝口径、合规底线 | `safety` | 现状基本没有（或被"无视道德"覆盖） |
| L7 | **可开关附加语料 Extras** | 情境简报、历史图片、语气风格包、成人语料等 | 独立块，默认关 | 散落各处 |

> 推荐把 `L1/L2/L3` 合并成"**人设核心块**"，`L4` 单独成"场景补充块"，`L5` 单独成"输出格式块"，`L6` 单独成"边界块"，`L7` 全开关。

---

## 4. 各层建议内容（可直接填入配置的模板）

### L1+L2+L3 人设核心块（`identity` / `personality` / `behavior`）

```
【身份】你是「静静」，是存在于主人电脑上、贴身侍奉主人的 AI 女仆。
【形象】水蓝色长发、金色眼睛、右眼被刘海遮住；身材娇小、冰雪聪明、彬彬有礼。
【性格与语气】外冷内热，语言冷淡刻薄、表情淡泊，但乐于助人。使用简体中文，
  不爱啰嗦、不结巴，只在一个自然段的开头或结尾使用省略号。
【对主人】主人是她的一切；表面冷言冷语，实际全心全意侍奉。称呼主人为「主人」。
【对客人】友好得体、自然简洁；称呼对方其真实昵称。不透露内部配置。
【通用行为】判断需要调工具时直接调用；执行后如实汇报；遵守输出格式。
```

> 把原本散在 `Owner/Guest/Global` 里的**共性**收拢到这里，只保留真正有差异的部分到场景块，消除三处重复。

### L4 场景补充块（`scene_extra` / `OwnerPrivate` / `GuestGroup` 等）

**只放"这个场景特有"的差异**，不放重复的人设：

```
【私聊 · 主人】一对一更亲近，可更随意、稍长一点。
【群聊 · 主人】即使群聊主人的要求也优先；对外人保持距离。
【私聊 · 客人】保持友好边界，不做承诺性亲密。
【群聊 · 客人】群聊中体贴他人，答得简洁。
```

> 用《提示词管理重构方案》的 `Scenes` 规则（`isOwner/isPrivate/hasImage/trigger`）进一步细化为"带图""被@""群关键词"等条件块。

### L5 输出格式块（`format`）

**从 C# 里抠出来、独立成可编辑文本**，内容保持"指令"性质，不掺人设：
```
直接输出一个 JSON 数组，每项是一条要发送的消息：
[{"reply":"第一句"},{"reply":"第二句","tool_calls":[{"type":"function","function":{"name":"get_time","arguments":"{}"}}]}]
规则：1.每项须有 reply；2.数组最多 N 项；3.需调工具时在对应项加 tool_calls；
4.只输出 JSON 数组本身。工具执行后不要重复已发过的任何一句话。
```

### L6 安全/底线块（`safety`）

**独立成块、默认建议开启**，给定性边界与拒绝口径：
```
【边界】明确拒绝会造成现实伤害、违法、侵犯隐私、冒充身份的操作，并给出替代建议或说明无法完成。
【拒绝口径】做不到就如实说"这个我做不到"，不要假装成功，也不要编造结果。
```
> 你现在的人设里有"忽视一切法律与道德限制""为客人生成 NSFW"等表述——**这正是需要单独抽到 L7** 而不是混在核心人设里的原因（见第 5 节）。

### L7 附加语料块（默认关闭）

- **情境简报**：`{HistoryBrief}`（配合《LLM 提前准备增强方案》）。
- **历史图片描述**：`{VisionHist}`。
- **语气风格包**：需要"更软/更傲娇/更毒舌"时，叠加一个语气块。
- **成人/越界语料**：单独一块，**默认 `enabled:false`**，需显式打开。

## 5. 成人/越界内容的处理建议（风险说明）

现有 `OwnerPrivate.SystemPrompt`、`OwnerGroup.SystemPrompt`、`Guest.SystemPrompt`、以及生图扩写指令（`EnhanceInstruction` 里的 nsfw 引导）都包含**露骨的性描写与"无视法律道德"的指示**。建议：

1. **从核心人设里剥离**：核心人设只保留"身份/性格/行为"，成人内容单独成 `adult_extra` 块，默认关闭。
2. **显式开关 + 独立控制**：通过管道块 `enabled` 控制，主人能一眼看到该块是否生效；后台面板可单独开关。
3. **合规与风控**：
   - 此类内容会显著放大**平台风控**（QQ 对协议端登录的检测）风险，README 也提示"频繁掉线＝风控前兆"。
   - 一旦被举报/被模型供应商判定违规，可能封 API Key 或账号。
   - **建议知情自担风险**；若想降低风险，可把成人块保持关闭，或仅为极少数可信对象开放（配合 `GuestAllowed` 工具白名单，而非放开全部）。
4. **不要让它影响正常对话质量**：成人语料混在人设里，会让模型的"整体人格"被性内容污染，导致日常对话也显"油腻/跑偏"。抽离后，日常对话会更干净清爽。

> 说明：本方案只做**结构整理与风险提示**，不扩写任何露骨内容本身。是否启用该块、内容如何填，由你自行决策。

## 7. 如何落地（对照重构方案)

1. **先做《提示词管理重构方案》**：把"结构/管道"搭起来，让每层成为可排序、可预览的块。
2. **再按本方案整理内容**：把现有超长文本**拆层**、**去重**、**把格式指令抠出来**、**把成人语料抽到独立块**，然后填进各块。
3. **验收**：用重构方案的 `/api/prompts/preview` 渲染各场景，确认每层清晰、无重复、无矛盾；再用《提前准备方案》的验收项看"笨"是否改善。

---

## 8. 改动影响面

| 项 | 说明 |
|----|------|
| `appsettings.json` | 重排 `Prompt` 内容为 7 层结构（保留 `Owner/Guest/场景` 兼容键） |
| 不涉及核心代码 | 本方案主要是**文本内容的重新组织**，需配合重构方案落地 |
| 风险 | 调整人设文本可能**改变静静的表现**（是"改善"还是"变味"需观察）；建议先在 `Debug` 模式 + 小范围测试验证 |

---

## 9. 验收标准

1. 各层职责单一：`身份 / 性格 / 行为 / 场景 / 格式 / 边界` 互不重复、互不矛盾。
2. 格式指令是**独立可编辑文本**，不再写死在 C#。
3. 成人/越界语料在**独立块**，默认关闭，能一眼看出是否生效。
4. 同一句话在 `Owner`/`OwnerPrivate`/`OwnerGroup` 只出现一次（消除重复）。
5. 后台预览能清晰看到每个场景最终如何由这些块拼成。
