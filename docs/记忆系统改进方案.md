# 记忆系统改进方案

> 状态：方案讨论完成。**第一批已于 2026-08-06 实施完成**（两步定位检索 + 群聊 bug 修复 + function call 总结 + 去重合并 + 衰减升温 + 工具描述外部化 + !summarize 命令 + 数据清理）。第二批/第三批待实施。
> 原则：**越人工越智能** —— 确定性结构（QQ号/群号/索引）管定位，模型只负责最后一环语义筛选。

## 一、现状问题

| 面 | 问题 |
|---|---|
| 写入 | 每轮对话都后台总结，噪音大、碎片多；总结 prompt 无正反例，一次性事件也被记 |
| 存储 | 记忆只增不减、重复堆积；**群聊记忆 bug：qq_id 为 NULL 的 user 记忆任何场景都检索不到（写了白写）** |
| 提取 | 全库扫 200 条再关键词子串匹配，粗糙；重要度≥4 无条件常驻注入，与话题无关也塞 |
| 注入 | 干巴巴清单、无语境、无使用引导，LLM 容易"背诵"破坏角色扮演 |

## 二、目标架构

```
写入三层：当场(remember 工具,保守) + 沉淀(后台累积总结,function call) + 手动(!summarize 命令)
存储三类：user(qq_id) / group(group_id) / global
提取两步：① 结构化定位(SQL 走索引) → ② 语境筛选(触发词+2-gram 相关度)
注入格式：带使用引导 + 来源语境 + 相关度优先
```

## 三、具体设计

### 1. 写入：三层机制

- **当场层（对话中）**：`remember` 工具保持保守——仅用户明确要求（"记住…""帮我记下…"）或表达强烈明确长期偏好/承诺时调用。不开放批量记忆工具给对话（防随意）。
- **沉淀层（后台）**：累积式总结——攒 N 条新消息（建议 6~10）才触发一次；**指令放消息队列最后一条**（利用近因效应）；改用 **function call** 让 LLM 调用 `save_memories` 工具传结构化参数（零 JSON 解析、零格式错误），`tool_choice` 强制调用，空数组=没值得记的。
  - 总结指令正反例：只记可复用长期事实（偏好/身份/习惯/承诺/关系）；**禁记一次性事件**（吃了什么/去哪/临时心情）。
  - 重要度保守：默认 1~3；反复提及/主人明确要求才 4~5。
  - 群聊总结写入 `group(group_id=本群)`；涉及具体某人时可双写 `user(qq_id=该人)`。
- **手动层（命令）**：新增 `!summarize` —— `!summarize`（当前会话）/ `!summarize <QQ号>` / `!summarize group <群号>`，主人随时触发总结最近对话。

### 2. 存储：生命周期

- `Memories` 加列：`group_id INTEGER`（群归属）、`last_used_at TEXT`、`use_count INTEGER DEFAULT 0`。
- **去重合并**：新记忆与同 scope 记忆做 2-gram Jaccard 相似度，>0.45 视为同主题——保留旧 id，content 取信息更全的，trigger 取并集，importance=max，刷新 updated_at。
- **衰减升温（用进废退）**：惰性计算有效重要度 = `importance - 0.1 × 距上次衰减天数`（加 `decay_at` 列记录）；被唤起命中时 `use_count++`、`last_used_at=now`、+0.2 升温。≤2 星且 30 天未用 → 整理删除候选。
- **数据迁移**：清理现有 qq_id=NULL 的 user 记忆（群聊幽灵数据）。

### 3. 提取：两步定位

- **第一步 结构化定位（人工规则，SQL 走索引）**：
  - 私聊：`user(qq_id=对方) ∪ global`
  - 群聊：`group(group_id=本群) ∪ user(说话人) ∪ global`
  - 提及他人：消息中 @ 的 QQ / 正文 QQ 号（正则）→ 额外搜他们的记忆
- **第二步 语境筛选**：候选集内触发词 + 2-gram 相关度 → 重要度排序 → 取最相关 N 条。
- **正则硬事实通道**（可配置词表）：QQ号/日期/时间/金额/词表+宾语 模板，写入时补 trigger、检索时直接召回。
- **4 星不再无条件常驻**：5 星才常驻；4 星仅在相关时注入。

### 4. 注入：语境化格式

```
【你记得的长期记忆】这些是从对话中沉淀下来的，回复时自然提及即可，
不要一次性倒出来，更不要生硬背诵——只在你觉得相关时提起。
- 之前主人聊过：喜欢喝奶茶，冬天要热的（偏好 ★4）
- 主人家里养了只白猫叫"咪咪"，提起过多次（身份 ★5）
```
- 每条带来源语境（"之前主人聊过…"）；排序相关度优先、重要度次之；来源可信度分层（明确要求>后台总结>全局）。

### 5. 工具描述外部化

- appsettings.json 新增 `Bot.Tools.Descriptions`（工具名 → 描述），空值用代码默认、填写即覆盖。
- 覆盖点集中在 `ToolRegistry.BuildToolDefinitions()` 一处（主对话与自主活动共用此生成器，一次生效）。
- 覆盖的工具：get_time / remember / search_memory / send_text / browse_web / generate_image / run_shell / send_private_to_owner / send_group_message / organize_memory。

### 6. 命令提示词（可选）

- `BuiltinCommands.Catalog` 的命令描述同样可考虑外部化（`Bot.Commands.Descriptions`），视需求再做。

## 四、实施分批建议

- **第一批（核心）**：两步定位检索 + group_id 写入归属（修群聊 bug）+ function call 总结（指令放最后）+ 去重合并 + 衰减升温 + 工具描述外部化 + `!summarize` 命令 + 数据清理
- **第二批**：写入门控（信息密度）+ 累积式总结调参 + 正则硬事实通道
- **第三批**：自动记忆整理（自主活动内）+ 注入语境化格式 + 反馈闭环（"不用记/记错了"）
