# QQ 机器人提示词管理重构方案（Prompt Pipeline）

> 版本：v1.0 ｜ 日期：2026-08-26 ｜ 状态：待评审
> 目标：让「每次唤醒发给 LLM 的完整提示词结构」**透明可见、顺序可调、内建提示词可编辑、场景配置更灵活**。
> 本方案**只做设计，不改代码**；评审通过后再按「实施建议」分阶段落地。

---

## 0. 一句话概括

把 `EventDispatcher` 里**硬编码串联**的提示词组装，改成一个**声明式模板管道**：

```
配置里维护一份有序的 "Prompt 块清单"（每块 = id + role + 模板 + 开关 + 顺序）
渲染器按顺序把每块替换占位符 → 拼接成 head / tail
剩下的历史消息 / 工具回填 / 任务目标 / 回复数组 仍由引擎动态生成
```

好处：**块顺序在配置里可调**、**每块内容可见可改**、**写死在 C# 里的内建提示词也能覆盖**、**完整渲染结果可在后台一键预览**。

---

## 1. 目标与范围

### 1.1 要达到的效果（对应你的三个痛点）

| 痛点 | 本方案如何解决 |
|------|----------------|
| 无法得知每次唤醒发送的**完整提示词结构** | 提供 `Prompt 预览`：按场景渲染出最终发给 LLM 的 head / system / tail / 底部指令全文；且每块带来源标注（config / builtin） |
| 无法**编辑它们的顺序**和一些内建提示词 | 块清单放在 `appsettings.json`，`Head/Tail` 数组**顺序即渲染顺序**；写死在 C# 里的内建提示词挂到 `Overrides` 可覆盖 |
| 缺乏不同场景下的**灵活配置** | 场景由「身份 × 场景」**升级为规则化匹配 + 分层 Extra 追加**，支持条件表达式（带图 / 被@ / 群聊关键词等） |

### 1.2 明确的边界

- **不改** LLM 调用协议、工具系统、记忆提取算法、生图/识图流程（这些只复用，不动）。
- **只重构**「提示词如何组装、如何呈现、如何编辑」这一层。
- **保持向后兼容**：默认配置下，渲染出的提示词结构和现在**完全一致**，不影响现有对话表现。

## 2. 现状诊断（对照代码，定位"乱"的根源）

### 2.1 当前提示词是"几段硬拼 + 顺序写死在 C#"

`EventDispatcher.HandleChatAsync` 里，最终消息由**四段**拼成，段内顺序不可配置：

| 段 | 构成 | 位置 | 角色 | 可否编辑 |
|----|------|------|------|----------|
| `head` | `GlobalPrePrompt` + `system` | 历史前 | `GlobalPrePromptRole` / `system` | Global②可；system 内容缺省 |
| `system` | **一坨 join 在一起的 parts**：身份提示词`BuildSystemPrompt(Pre+System+Post)` + 场景Extra + 对话人身份行 + 记忆注入 + 上次规划 + 引用上下文 + 识图描述 + 群聊上下文提示 | 历史前 | `system` | parts 里部分可编辑，但"这一整块"无法拆分/排序 |
| `tail` | `GlobalPostPrompt` | 历史后、生成位前 | `GlobalPostPromptRole` | 可 |
| 底部 | `formatMsg` = `BuildFormatInstruction(...)` | 最底部（贴近生成位） | `user` | **❌ 写死在 C#** |

另外，历史消息 / 图片嵌入 / 任务目标提示 / roundMsgs（工具回填）由引擎动态生成，属**数据**而非模板，仍归代码管（合理，保留）。

### 2.2 写死在 C# 里、配置改不到的提示词（重点）

| 提示词 | 位置 | 现状 |
|--------|------|------|
| 回复格式指令 `BuildFormatInstruction` | `EventDispatcher` ~L1114 | 回复数组格式 + 防重复 + 工具调用示例 + 记忆工具例外，全部硬编码（仅 `delimiter`/`MaxRepliesPerTurn` 取自配置） |
| 格式纠正提示 `BuildCorrectionMessage` | `EventDispatcher` ~L405 | 硬编码 |
| 规划默认模板 `DefaultPlanningPrompt` | `EventDispatcher` ~L1075 | 硬编码（`Bot:Prompt:PlanningPrompt` 可覆盖，但**不在后台 PromptDefs 里**） |
| 记忆总结 system/指令 | `MemoryService` ~L158~168 | 硬编码（`save_memories`） |
| 记忆整理 system/指令 | `MemoryService` ~L271~278 | 硬编码（`review_memories`） |
| 自动活动 system/行动说明 | `AutoActivityOptions.SystemPrompt` | **可编辑**（配置）；但行动清单 `BuildActionsText` 部分拼装逻辑在代码 |
| 生图扩写指令 / 识图描述 | `ComfyUI.EnhanceInstruction` / `Vision.DescribePrompt` | **可编辑**（配置） |

> **结论**：不是"没有提示词管理"，而是**管理只覆盖了配置里存的那一半**；写死在 C# 的那一半、以及"顺序/整块结构"完全没有入口，这才是"乱"的真正来源。

### 2.3 后台面板现状（`AdminService`）

- 已有 `GET/PUT /api/config/prompts`，但 `PromptDefs` 只登记**配置路径**内的字段：`GlobalPrePrompt(Role)`、`GlobalPostPrompt(Role)`、`Owner/Guest × 四种场景` 的 System/Pre/Post/Extra。
- 它**看不到** `BuildFormatInstruction` 等内建提示词，也**没有顺序控制**和**渲染后预览**，更没有"某场景最终发给 LLM 的完整 messages 总览"。

**改进应在此基础上扩展**，而不是重造一个编辑系统：复用 `SaveConfigUpdatesAsync`（写回 appsettings 保留注释 + 同步 src + 热更新重绑定）这套机制。

## 3. 总体设计原则

1. **单一事实来源**：提示词文本要么在配置、要么在"内建默认值(可被配置覆盖)"，不允许出现"配置改不了的第二份硬编码文本"。
2. **结构与内容分离**：**结构**（块顺序、开关）放配置；**内容**（每块文本）放配置或内建默认。顺序和内容都能改。
3. **透明可审计**：任何场景都能渲染出最终 messages 并预览，带每块来源与命中规则。
4. **向后兼容**：默认配置 = 现状行为；不主动改变既有 LLM 表现。
5. **热生效**：沿用现有模式，渲染时动态读配置（后台面板改完即时生效，无需重启）。

## 4. 核心概念：声明式 Prompt 管道（Prompt Pipeline）

### 4.1 概念图

```
【配置 · Prompt】
├─ GlobalPre / GlobalPost / Owner / Guest / 场景 Profile   ← 保留，作为"块内容源"
├─ Head:  [ {id, role, content|source, enabled}, ... ]     ← ★ 新增：有序块清单（历史前）
├─ Tail:  [ {id, role, content|source, enabled}, ... ]      ← ★ 新增：有序块清单（历史后 → 底部）
└─ Overrides: { builtinId: "覆盖文本", ... }                ← ★ 新增：覆盖写死在 C# 的提示词

【渲染器 PromptRenderer】接收：场景上下文 + 动态数据
   按 Head 顺序 → 逐块替换占位符 → 追加到 head
   （引擎在此之后插入 历史/图片/任务目标/roundMsgs）
   按 Tail 顺序 → 逐块替换占位符 → 追加到尾部
   （规划、格式指令都作为 Tail 块，顺序可控）

【输出】List<ChatMessage> = head + 历史/数据 + tail
```

### 4.2 块（PromptBlock）模型

```csharp
record PromptBlock(
    string Id,            // 稳定标识，如 "global_pre" / "identity" / "memory" / "format"
    string Role,          // system | user | developer
    string? Content,      // 直接文本（配置里填了就用它）
    string? Source,       // 为空则用 Content；否则引用配置字段或内建默认
    bool Enabled);        // 开关
```

- **`Content` 优先**：配置里直接给了文本，就用它。
- **`Source` 引用**：`Config:Owner:SystemPrompt`、`Config:GlobalPrePrompt` 等指到现有配置字段；或 `Builtin:format`（内建默认，可用 `Overrides` 覆盖）。
- **`Enabled`**：可在后台一键开关某一块（如临时关掉"上次规划"注入）。

### 4.3 锚点（决定块放哪）

改造成本最低的锚点，分两组：
- **`Head`**：历史前的 system 类消息（目前是 `GlobalPre` + 一大坨 `system`）。
- **`Tail`**：历史后、roundMsgs 前的消息（目前是 `GlobalPost` + `formatMsg`；规划也在这一区间）。

这样**不用动**引擎里"插历史/插图片/插任务目标"的逻辑，只把"提示词模板如何生成"换成管道渲染。

> 兼容性开关：`MergeSystemIntoOne`（默认 `true`）= 把 Head 里所有 `role=system` 的块 join 成**一条** system（和现在一致）；`false` = 每块一条独立消息（更细粒度方便调试，模型也更能区分职责）。建议先 `true` 保证不回归，稳定后再试点 `false`。

## 5. 配置结构（appsettings.json 示例）

```jsonc
"Bot": {
  "Prompt": {
    // —— 保留（现有字段，作为块的"内容源"）——
    "GlobalPrePrompt": "...", "GlobalPrePromptRole": "system",
    "GlobalPostPrompt": "...", "GlobalPostPromptRole": "user",
    "Owner": { "SystemPrompt": "...", "PrePrompt": "", "PostPrompt": "" },
    "Guest": { ... },
    "OwnerPrivate": {...}, "GuestPrivate": {...}, "OwnerGroup": {...}, "GuestGroup": {...},
    "PrivateExtra": "...", "GroupExtra": "...",
    "MaxContextMessages": 50, "AutoInjectGroupHistory": true,

    // —— ★ 新增：有序块清单（历史前）——
    "Head": [
      { "id": "global_pre",   "role": "@GlobalPrePromptRole", "source": "Config:GlobalPrePrompt", "enabled": true },
      { "id": "identity",     "role": "system", "source": "SceneResolve", "enabled": true },
      { "id": "scene_extra",  "role": "system", "source": "SceneExtra",  "enabled": true },
      { "id": "person",       "role": "system", "source": "Builtin:person_line",  "enabled": true },
      { "id": "memory",       "role": "system", "source": "Builtin:memory_injection", "enabled": true },
      { "id": "last_plan",    "role": "system", "source": "Builtin:last_plan", "enabled": false },
      { "id": "quote",        "role": "system", "source": "Builtin:quote_context", "enabled": true },
      { "id": "vision",       "role": "system", "source": "Builtin:vision_desc", "enabled": true },
      { "id": "group_hint",   "role": "system", "source": "Builtin:group_context_hint", "enabled": true }
    ],

    // —— ★ 新增：有序块清单（历史后 → 底部）——
    "Tail": [
      { "id": "global_post", "role": "@GlobalPostPromptRole", "source": "Config:GlobalPostPrompt", "enabled": true },
      { "id": "planning",    "role": "user", "source": "Builtin:planning", "enabled": "@Planning.Enabled" },
      { "id": "format",      "role": "user", "source": "Builtin:format",  "enabled": true }
    ],

    // —— ★ 新增：覆盖写死在 C# 的内建提示词 ——
    "Overrides": {
      "format": "",                        // 留空=用内建默认 BuildFormatInstruction
      "correction": "",                    // BuildCorrectionMessage
      "planning": "",                      // DefaultPlanningPrompt / Bot:Prompt:PlanningPrompt
      "memory_summary_system": "",
      "memory_summary_user": "",
      "memory_organize_system": "",
      "memory_organize_user": "",
      "person_line": "",
      "memory_injection": "",
      "last_plan": "",
      "quote_context": "",
      "vision_desc": "",
      "group_context_hint": ""
    },

    // —— ★ 可选：本次只做设计，预留（见第 7 节）——
    // "MergeSystemIntoOne": true,
    // "Scenes": [ { "id": "...", "match": {...}, "priority": N, "extraHead": [], "extraTail": [] } ]
  }
}
```

> 说明：
> - `role: "@GlobalPrePromptRole"` 表示取值引用——渲染时读配置那个字段作为 role（保留现有行为）。
> - `source: "Builtin:xxx"` 指向代码内建默认；`Overrides["xxx"]` 非空则优先，**实现了"内建提示词可编辑"**。
> - `source: "SceneResolve"` / `"SceneExtra"` 走现有 `ResolveScene(...)`（保留身份×场景回退逻辑）。

## 6. 内建提示词清单与覆盖机制（"现在改不到的"如何变得可编辑）

### 6.1 内建提示词注册表

代码内新增一个 `BuiltinPromptDefaults` 静态表，登记所有**曾在 C# 里写死**的提示词，给每个一个稳定 id + 默认文本：

| builtin id | 对应现状 | 说明 |
|------------|----------|------|
| `format` | `BuildFormatInstruction` | 回复数组格式 + 防重复 + 工具调用示例 + 记忆工具例外 |
| `correction` | `BuildCorrectionMessage` | 格式不合格时的纠正提示 |
| `planning` | `DefaultPlanningPrompt` / `PlanningPrompt` | 规划轮提示 |
| `person_line` | `HandleChatAsync` 里的"当前对话人"行 | 身份称呼/描述 |
| `memory_injection` | `BuildMemoryInjection` | **记忆注入**（含"你记得的长期记忆"措辞） |
| `last_plan` | `SavePlanning→注入` 那段 | 上次规划延续提示 |
| `quote_context` | 引用上下文提示（含"如需转发…"） | 被引用消息 + 转发引导 |
| `vision_desc` | 识图描述注入提示 | "【图片内容】…" |
| `group_context_hint` | 群聊外置时的"上下文提示" | 未注入历史时提示调 `get_chat_history` |
| `memory_summary_system` / `memory_summary_user` | `MemoryService` L160~167 | 对话后记忆总结（`save_memories`） |
| `memory_organize_system` / `memory_organize_user` | `MemoryService` L271~277 | 自动记忆整理（`review_memories`） |

### 6.2 覆盖规则

```
最终文本 = Overrides[id]（非空） ？ Overrides[id]  : BuiltinPromptDefaults[id]
```

- 这些文本在**渲染时读取**，后台改 `Overrides` 后**即时生效**。
- `memory_summary_*` / `memory_organize_*` 属于记忆子系统的内建提示，物理上在 `MemoryService`，但**统一走同一个覆盖注册表**，避免"记忆只有一套还改不了"。

## 7. 场景匹配模型（从"4 个固定场景"到"规则化 + 分层追加"）

### 7.1 现状与局限

现在只在 `ResolveScene` 里按 `身份(Owner/Guest) × 私聊/群聊` 定 4 个场景 Profile（`OwnerPrivate/GuestPrivate/OwnerGroup/GuestGroup`），且场景内固定只支持 System/Pre/Post/Extra 四个字段。**加新条件**（带图、被@、群关键词、晚高峰……）只能改代码加分支。

### 7.2 设计：基础场景 + 条件规则叠加

1. **基础场景**仍由 `身份 × 私聊/群聊` 决定（回退链不变，兼容现有配置）。
2. **新增 `Scenes` 规则列表**（可选，向后兼容）：按 `priority` 匹配，命中则在此场景上**追加/覆盖**若干 Head/Tail 块。
3. 匹配条件（`match`）用一个小的求值器：
   ```jsonc
   "Scenes": [
     {
       "id": "owner_private_with_image",
       "priority": 1,
       "match": { "isOwner": true, "isPrivate": true, "hasImage": true },
       "extraTail": [
         { "id": "img_note", "role": "system",
           "content": "对方发了图，先用描述理解图片，再结合上下文回复。", "enabled": true }
       ]
     },
     { "id": "group_at_no_keyword", "priority": 2,
       "match": { "isPrivate": false, "trigger": "at" },
       "extraTail": [ { "id": "group_short", "role": "system", "content": "群聊被@，回答简洁、点到为止。", "enabled": true } ] }
   ]
   ```
4. `match` 支持字段：`isOwner`、`isPrivate`、`hasImage`、`trigger(at|keyword|reply)`、`mention(是否@了别人)`、`groupId`、`hourRange`（可选扩展）。
5. 未命中规则时，用基础场景 + 全局 Head/Tail；命中多条规则按 `priority` 从高到低叠加 `extraHead/extraTail`。

> 这是一层**渐进式**能力：先不配 `Scenes` 就完全等同于现在的 4 场景；想加条件再往里加规则，**不用改代码**。

## 8. 渲染器（PromptRenderer）

### 8.1 统一占位符

现状占位符分散：对话里 `{UserName}/{UserQQ}/{OwnerId}`；生图 `{Prompt}/{QualityTags}/{Negative}`；自主活动 `{Actions}/{Memories}/…`。统一到一个渲染器，支持：

| 占位符 | 说明 |
|--------|------|
| `{UserName}` `{UserQQ}` `{OwnerId}` | 对话人/主人（现有） |
| `{Scene}` | 场景标签（private/group×owner/guest） |
| `{Identity}` | 身份名（owner/guest） |
| `{DateNow}` | 当前时间 |
| `{HistoryBrief}` | 历史简报（见 8.2） |
| `{{` `}}` | 转义（模板里要输出字面 `{` 用 `{{`） |

### 8.2 历史简报占位（为后续"治笨"预留，本次不实现）

`{HistoryBrief}` 预留：把最近历史压缩成省略版（见另一份《LLM 提前准备增强》方案的"历史摘要"）。本次仅预留占位与渲染钩子，不实现摘要算法。

### 8.3 渲染流程

```
RenderHead(sceneCtx):
  forens = sceneCtx.blocks = ResolveBlocks(sceneCtx)   // Head 清单 + Scenes 叠加
  foreach block in blocks (Enabled):
      text = ResolveText(block)          // Content or Source or Builtin/Override
      text = Substitute(text, placeholders, sceneCtx.dynamic)
      if text non-empty: emit (block.Role, text)   // 或 join 到 system（MergeSystemIntoOne）
```

## 9. 完整预览 & 可视化编辑（AdminService 扩展）

在现有 `GET/PUT /api/config/prompts` 基础上扩展，**复用** `SaveConfigUpdatesAsync` 写盘/热更新逻辑：

| 新接口 | 作用 |
|--------|------|
| `GET /api/prompts/registry` | 返回全部**可编辑提示词**清单，含来源标记（config / builtin）、当前生效值、覆盖与否。内建提示词(`Builtin:format` 等)也一并列出——**解决"改不到内建提示词"** |
| `GET /api/prompts/preview?scene=...&uid=...` | **渲染该场景最终 messages 全文**：逐块显示 role + 来源 + 文本 + 命中规则，历史/图片/roundMsgs 用占位标注。**解决"不知道发了什么"** |
| `PUT /api/prompts/order` | 保存 `Head/Tail` 块顺序（数组顺序）+ 每块 `enabled` |
| `PUT /api/prompts` | 沿用现有 `SaveConfigUpdatesAsync` 保存各文本字段 |

**前端"提示词"页改造**：
1. **块视图**：Head/Tail 两列，可拖拽排序、每块可开关、点开显示该块当前渲染文本与来源。
2. **内建提示词页签**：列出 `format/correction/planning/memory_*` 等，文本框可覆盖（留空=用内建默认）。
3. **预览面板**：选场景 → 显示完整 messages 总览，带"发送前预览"。

## 10. 兼容与迁移策略

### 10.1 兼容保证

- `Head`/`Tail` **默认数组**即复刻现状顺序与内容（第 5 节示例即默认）。
- `GlobalPre/GlobalPost/Owner/Guest/场景Profile` 字段**保留不动**，作为块内容源被引用。
- `MergeSystemIntoOne=true` 时，`identity..group_hint` 仍 join 成一条 system → 与现在**逐字一致**。
- 新增字段全部**可选**；`Overrides` 空、`Scenes` 空、`Tail` 不含 `planning` 时行为完全不变。

### 10.2 迁移路径

1. **阶段 A（无感）**：加 `BuiltinPromptDefaults` + `PromptRenderer` + `Head/Tail` 默认值；`EventDispatcher` 改为调用管道渲染，但**用现状默认值 + MergeSystemIntoOne=true**，跑一次回归确认无差异。
2. **阶段 B（可编辑内建）**：把 `format/correction/planning/memory_*` 走 `Overrides` 覆盖；后台注册表暴露 `Builtin:*` 项。
3. **阶段 C（可排序/可开关）**：面板支持拖拽 Head/Tail 排序 + 每块开关。
4. **阶段 D（场景规则 + 预览）**：实现 `Scenes` 匹配与 `/preview` 渲染接口。
5. **阶段 E（可选）**：试点 `MergeSystemIntoOne=false`，观察效果后决定是否默认。

> 每个阶段独立可回滚、可验收；不一次性引入大改动。

## 12. 风险与权衡

| 风险 | 应对 |
|------|------|
| 拆块后若 `MergeSystemIntoOne=false` 可能改变 LLM 行为 | 默认 `true`，独立 A/B 观察；可逐场景切换 |
| 场景规则求值器复杂度上升 | `match` 用白名单字段，不做任意表达式；配错不影响默认场景 |
| 内建提示词文本迁移工作量大 | 分阶段：先跑通 `format/correction/planning`，再补 `memory_*` |
| 后台编辑写 appsettings 保留注释（现有 `SetJsonValue`） | 沿用现有实现，避免破坏注释 |

## 13. 验收标准

1. 后台"提示词"页能看到**当前配置 + 内建默认 + 覆盖值**三者关系。
2. 用 `GET /api/prompts/preview` 能渲染出某场景**最终 messages 全文**，与日志里实际发送内容一致。
3. 在后台改 `Overrides["format"]` → 立即影响回复格式指令，无需重启。
4. 在后台把 `Head` 里 `memory` 块拖到 `last_plan` 之后 → 渲染顺序随之改变。
5. 默认配置下，不配置任何新字段，机器人对同一消息的回复与重构前**一致**（回归通过）。
6. 新增一个 `Scenes` 规则（如`群聊被@`+`带图`），无需改代码即可在该场景追加提示词。
