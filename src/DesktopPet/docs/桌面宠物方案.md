# 静静桌面宠物方案（QQBot 之外的第一块新皮肤）

> 版本：v1.1 ｜ 日期：2026-09-20 ｜ 状态：P0/P1 已落地（P1 于 2026-09-20 完成）
> 一句话：**桌面宠物只做"前端"（窗口+PNG动作+气泡），人格、记忆、LLM 全部复用现有 QQBot 后端**——
> 让桌面上的静静和 QQ 里的静静是**同一个人**，而不是养出第二个精神分裂的分身。

## 1. 总体架构

```
┌───────────────────────────┐         ┌──────────────────────────────────┐
│  桌面宠物 DesktopPet.exe   │  HTTP   │  静静后端（现有 QQBot 进程）        │
│  WPF · 独立进程 · 托盘     │ ⇄ WS ⇄  │  /api/pet/chat  /api/pet/stream   │
│  ├ 透明置顶窗口            │         │  ├ 人设 / 记忆 / 上下文（同一套）   │
│  ├ PNG 动作播放            │         │  ├ DeepSeek（同一个模型配置）      │
│  ├ 气泡对话                │         │  ├ ComfyUI 生图（她可以现场画给你） │
│  └ 可换皮肤/气泡/字体       │         │  └ 自主活动（可以"爬"到桌面找你）   │
└───────────────────────────┘         └──────────────────────────────────┘
```

**为什么宠物要单独进程**：WPF 必须 STA + 自己的消息循环，塞进 ASP.NET 宿主里又别扭又容易死锁。
所以：QQBot 侧**新增一组 `/api/pet/*` 端点**（进程内 Minimal API，和后台面板同一套路），WPF 端只做前端。

**为什么不让宠物直连 DeepSeek**：那样人设要抄一份、记忆是第二套库、你教她的东西两边不同步。
桌面说"我今天不开心"，QQ 里的她一脸茫然——这种分裂比多写几个端点麻烦得多。

## 2. 协议草案（先定契约，再写两端）

### 已实现（P1）

| 端点 | 方向 | 用途 |
|---|---|---|
| `GET /api/pet/ping` → `{ok,enabled,sessionKey,ownerId,timeoutSeconds,serverTime}` | 宠物 → 后端 | 健康检查（桌面端启动时探一次，连不上直接说） |
| `POST /api/pet/chat` `{text}` → `{ok,replies:[…],elapsedMs}` | 宠物 → 后端 | 说话；`replies[].type` 为 `text` 或 `image`（image 带 `dataUrl`/`caption`） |

会话键：`Bot.Pet.SessionKey`（默认 `pet:{ownerId}`，独立一段对话；可改成 `private:{ownerId}` 与 QQ 私聊共用历史）。
认证：复用 `Admin.Token`（Bearer）；只监听 `127.0.0.1`。

**关键机制（后端）**：`Core/Pet/PetBridge.cs` 登记"当前正在处理的宠物会话"，期间该会话的回复
被 `PetSink` 截获而不发 QQ（`ReplyAsync` / `GenerateImageTool` 两条发送路径都做了改道），
请求结束一次性返回给桌面端。走的是和 QQ 消息同一套 `HandleCoreAsync`——
人设、记忆、工具、规划轮全都复用，所以桌面和 QQ 是同一个她。

### 已实现（P2 的轻量版：轮询式推送）

| 端点 | 方向 | 用途 |
|---|---|---|
| `GET /api/pet/inbox?since=N&online=1` | 宠物 → 后端 | **取她主动发来的消息**（自主活动时说给主人的话 / 图片），同时上报心跳 |
| `POST /api/pet/presence {online}` | 宠物 → 后端 | 明确上报"在不在"（托盘躲起来 / 退出时） |

- 后端 `PetBridge` 多了两件事：**在线状态**（心跳超时 `Bot.Pet.OfflineAfterSeconds` 判离线）+ **主动消息队列**（`EnqueuePush` / `PushesSince`，带 seq 去重、5 分钟 TTL、上限 50 条）
- 渠道选择发生在 `SendPrivateToOwnerTool`：**精灵在线 → 投队列弹气泡；不在 → 回落 QQ 私聊**；群聊永远走 QQ（不受影响）
- 自主活动提示词里会带上`【桌面状态】主人在/不在电脑前`，她自己也知道该不该打扰

### 后台可改精灵配置（2026-09-20 追加）

- 后端 `Core/Pet/PetConfigStore.cs`：`data/pet-config.json` = `{version, updatedAt, config}`，每存一次 version+1。
- 端点：`GET/PUT /api/pet/config`；心跳 `inbox` 响应带 `configVersion`。
- 桌面端：心跳发现版本变了 → 拉取 → `PetConfig.ApplyRemote()` 覆盖外观/行为 → `LoadSkin()` + 重建气泡 + 重新贴边。
  位置与本机连接设置（baseUrl/token/enabled）**不覆盖**；皮肤加载失败时保留现有皮肤（不会把宠物弄没）。
- 面板控件类型 `petcfg`（整行表单，自带保存按钮）；后端存的是配置本身，不是桌面端的文件——**两个工程之间没有路径耦合**。

### 待做（P2 剩余）

| 端点 | 方向 | 用途 |
|---|---|---|
| `GET /api/pet/stream`（WebSocket） | 后端 → 宠物 | 换成 WebSocket 推送（省掉 3 秒轮询延迟）；QQ 消息到达提示 |
| `GET /api/pet/state` | 宠物 → 后端 | 当前状态 → 决定放什么动作（心情/忙碌/睡觉） |

## 3. WPF 端的坑（先写下来，免得第二次踩）

| 需求 | 做法 | 坑 |
|---|---|---|
| 透明无边框浮窗 | `WindowStyle=None` `AllowsTransparency=True` `Background=Transparent` `Topmost=True` `ShowInTaskbar=False` | 必须 `AllowsTransparency` + `None` 同时给；开了透明就不能用某些特效（DropShadow 会糊） |
| 拖动 | `MouseLeftButtonDown` → `DragMove()` | 拖动时要临时禁掉点击穿透，否则按不住 |
| 点击穿透 | `SetWindowLong(GWL_EXSTYLE, WS_EX_TRANSPARENT\|WS_EX_LAYERED)` | 做像素级穿透（只有角色身体能点）要用 `UpdateLayeredWindow`，见 P4 |
| 托盘常驻 | `NotifyIcon`（WPF 引 WinForms）或 `H.NotifyIcon` | 直接用 WinForms 那个最省事，但要 `UseWindowsForms=true` |
| 气泡 | **独立**无边框窗口跟随（别塞进角色窗口） | 塞一起会撑大窗口、挡住鼠标、缩放时角色跟着变形 |
| 多屏/DPI | `PerMonitorV2` + 存位置到 `pet.json` | 换屏后位置飘走、缩放模糊 |
| 动作播放 | `Image` + `DispatcherTimer` 切帧（呼吸=缩放动画也行） | PNG 序列帧要注意锚点对齐，否则"走路"会滑步 |

## 4. PNG 素材（这是最容易被低估的一步）

现有 124 张是**整幅画面**，不是透明立绘。有两条路：

| 路线 | 做法 | 成本 / 效果 |
|---|---|---|
| **A. 抠现有图**（推荐先做） | 挑 3~5 张"动作干净"的图 → 自动抠图（我这边有图像处理能力，可批量） | 快（今天就能看到成品）；边缘可能有瑕疵，动作种类受限 |
| B. 出规范立绘 | 用 `jingjing` LoRA + `simple background` 生成 → 抠图 → 统一分辨率/锚点 | 好看、可批量做动作；要跑 ComfyUI + 调参，慢 |

**最小可用动作集**：`idle`(2~4 帧呼吸/眨眼)、`talk`(2~3 帧)、`happy`、`sleep`。
先只有 1 张静态图 + 缩放"呼吸"动画也能跑起来——别一上来就追求全套动作。

资源结构（可换皮肤）：
```
assets/jingjing/
  pet.json          # 动作定义/帧率/锚点/默认缩放
  idle/1.png 2.png …
  talk/…
  bubble/           # 气泡九宫格皮肤
```

### P1 落地情况

**后端（QQBot）**
- 新文件 `Core/Pet/PetBridge.cs`：`PetSink`（单次请求的回复收集器）+ `PetBridge`（会话登记表）
- `BotOptions.Pet`（`Enabled` / `SessionKey` / `TimeoutSeconds` / `MaxTextLength`）+ appsettings `Bot.Pet`
- `EventDispatcher.HandlePetAsync(text)`：伪造一条"主人私聊"消息（`IsPrivate=true`/`IsOwner=true`，伪消息 id 保证跨重启唯一），
  走同一套两级调度与会话锁；登记 sink 期间回复改道，不发 QQ
- `GenerateImageTool`：宠物会话下的文字/图片都进 sink（**在桌面让她画图，图不会再跑到 QQ 里去**）
- `AdminService`：`/api/pet/ping`、`/api/pet/chat`；面板新增「桌面宠物」配置组

**前端（DesktopPet）**
- `Pet/PetBackend.cs`：HTTP 通道（ping / chat，含超时与错误可读化）
- `Pet/WindowSnap.cs`：边缘吸附计算——四边判定、按所在显示器工作区、DIP↔物理像素换算
- `MainWindow`：`OnUserSaid` 改为异步走后端，多条回复逐条冒气泡；拖动松手/缩放后自动贴边（`DispatcherTimer` 缓动，因为 `Left/Top` 不是依赖属性）
- `BubbleWindow`：支持图片（她画了图直接在气泡里显示）
- `pet.json`：新增 `backend` 与 `snap` 段

**验证**：后端接口实测（ping/chat/错误令牌/端口不通四条路径）、会话独立落库（`pet:123456789`）、
吸附两种情形（离左边缘 18px → 贴到 left；离四边都远 → 原地不动）、客户端 HTTP 链路隔离测试。
