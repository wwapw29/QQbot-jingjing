# 静静桌面宠物（DesktopPet）

把静静从 QQ 里"请"到桌面上：一个透明置顶的 PNG 宠物 + 气泡对话框。
**人格、记忆、模型、工具全部复用 QQBot 后端**——桌面上的她和 QQ 里的是同一个人。

当前版本：**P1**（骨架 + 已接后端：能真聊天；生图会显示在气泡里）

---

## 跑起来

```
先开 QQBot（她的大脑在那边，端口 7088）
双击  启动静静.bat
或    src\DesktopPet\bin\Debug\net10.0-windows\DesktopPet.exe
```

首次启动她会蹲在**屏幕右下角**，位置会被记住（存用户目录，不污染素材包）。
启动时会探一下后端；连不上会直接在气泡里说"连不上 QQBot"，不会让你对着不说话的宠物发呆。

## 交互

| 操作 | 效果 |
|---|---|
| 左键拖动 | 把她挪走；**松手自动吸附屏幕边缘**（离哪条边近贴哪条，带缓动动画） |
| **双击** / 右键→说话… / 托盘"说话…" | 弹出输入框（Enter 发送、Esc 取消），她回几句就冒几个气泡 |
| 右键 | 菜单：说话 / 贴边 / 边缘吸附开关 / 置顶 / 放大缩小 / 挥挥手 / 打开日志 / 退出 |
| 托盘图标 | 双击找回她；右键：躲起来、贴边、吸附开关、置顶、缩放、退出 |
| 点气泡 | 立刻关掉当前气泡（不等它自己消失） |

她要是在聊天里画了图，图会**直接显示在气泡里**（不是发去 QQ）。
另外**她也能主动找你说话**（自主活动时）：只要你桌面上有她，她的话就弹成气泡；你把她藏起来/关了，她自动改发 QQ——见下面「她什么时候弹气泡」。

## 接后端（她的大脑）

`pet.json` 的 `backend` 段：

```jsonc
"backend": {
  "enabled": true,              // false = 回显模式（不连后端，只验证交互）
  "baseUrl": "http://127.0.0.1:7088",   // QQBot 后台地址
  "token": "change-me",    // QQBot 的 Admin.Token
  "timeoutSeconds": 180,        // 她要规划/查记忆/调工具，别设太短
  "replyGapMs": 900             // 多条回复之间的气泡间隔
}
```

后端侧（QQBot）：`Bot.Pet.Enabled` 开关、`Bot.Pet.SessionKey` 决定桌面算不算独立的一段对话
（默认 `pet:{ownerId}` 独立；改成 `private:{ownerId}` 就与 QQ 私聊共用同一段历史）。面板「开关 → 桌面宠物」里能改。

协议：
- `GET /api/pet/ping` — 健康检查（含 `online`：她认为你在不在电脑前）
- `POST /api/pet/chat {"text":"..."}` → `{"ok":true,"replies":[{"type":"text","text":"…"} | {"type":"image","dataUrl":"…","caption":"…"}]}`
- `GET /api/pet/inbox?since=N&online=1` — 轮询：取她主动发来的消息（`pushes`），同时上报心跳
- `POST /api/pet/presence {"online":false}` — 明确上报"我不在了"
- `GET /api/pet/config` — 取后台配置（心跳返回的 `configVersion` 变了才需要拉）

## 后台改外观（不用碰本机的 pet.json）

QQBot 面板 →「开关 → **桌面精灵 → 精灵外观与行为**」有一张完整表单：名称 / 皮肤目录 / 缩放 / 置顶 / 呼吸 /
气泡（颜色·字体·字号·圆角·最大宽·自动消失）/ 边缘吸附 / 动作帧 / 心跳节奏。**点保存后几秒内自动套用**，不用重启她，
也不用去改桌面端的文件——桌面端每 3 秒心跳时会发现配置版本变了，自己拉一份换上。

- 备份文件在 QQBot 那边：`data/pet-config.json`（带版本号，每存一次 +1）
- **位置不动**；**后端的地址与令牌是桌面端本机设置，面板改不了**（改错了就连不上、连不上就再也拿不到配置）
- 本地 `pet.json` 仍然是"默认值"：后台配置只覆盖它写了的字段
- 皮肤目录写错也不会把她弄没——加载失败时保留当前皮肤并提示

## 她什么时候弹气泡（在线状态）

桌面端每 `backend.inboxPollMs`（默认 3 秒）向后端轮询一次——这个轮询**同时是心跳**：

- **她在屏幕上（没躲）** → 后端判定「主人在电脑前」→ 她自主活动想找你时，话会**弹成桌面气泡**
- **你把托盘「躲起来」/退出** → 立刻上报离线（或 15 秒没心跳自动判离线）→ 她改成**发 QQ 私聊**
- 后端判定阈值可在面板「桌面宠物 → 判定离线（秒）」改；群聊功能完全不受影响

这样"她在不在"就决定了她找你的方式，不会出现"弹了个气泡但你早关掉她了"。

## 边缘吸附

`pet.json` 的 `snap` 段：

```jsonc
"snap": { "enabled": true, "threshold": 36, "animate": true }
```

- 四条边都算：左 / 右 / 工作区顶 / **工作区底（任务栏上沿，站上去最自然）**
- 只在松手位置离某条边 ≤ `threshold` 时才吸，离得远就原地不动（不硬拽）
- 按**她所在那块屏**的工作区算，多显示器不会吸到主屏去；工作区=不含任务栏，所以不会被任务栏压住
- 屏幕缩放不是 100% 时会做 DIP↔物理像素换算（否则会吸错位置）
- 右键/托盘可临时关掉吸附

## 拖动缩放 / 锁定 / 打游戏时防误触

| 想做的事 | 怎么做 |
|---|---|
| **拖动** | 按住她拖（锁定状态下拖不动，会提示"解锁"） |
| **拖动缩放（保持比例）** | 鼠标移到她身上 → 右下角出现**斜纹手柄** → 按住拖。只改一个缩放系数，宽高同乘，**比例不会被拖歪**；斜着拖也跟手 |
| **精确缩放** | 右键 → 放大 / 缩小 / 重置大小（每次 15%） |
| **锁定位置和大小** | 右键 或 托盘 →「锁定位置和大小」。锁定后拖不动、缩放手柄自动隐藏（防手滑把她挪走）；**双击说话仍然可用** |
| **打游戏时别挡操作** | 默认开启「游戏模式防误触」：判定为"游戏中"时整只宠物**鼠标穿透**（点一下直接落进游戏，绝不会误触到她）。要跟她说话走**托盘菜单 → 说话…** |
| 托盘找回 | 不管锁没锁、穿透没穿透，托盘图标始终能叫她出来 / 说话 / 改开关 |

这几个开关也能在后台面板「桌面精灵 → 精灵外观与行为」里改（`locked` / `clickThroughInGame`），保存后她几秒内自己套用。

> ⚠️ 鼠标穿透期间**她自己也点不动**（包括右键菜单）——这是刻意的防误触。想改回来：托盘右键 →「游戏模式防误触」取消勾选，或者等她退出游戏模式自动恢复。

### 为什么手柄是 30x30 却只画一个小箭头（踩过的坑）

窗口开了 `AllowsTransparency`，Windows 对这类**分层窗口是按像素 alpha 判定命中**的：**alpha=0 的像素鼠标直接穿透给后面的窗口**。

于是"看得见"和"摸得到"是两回事——角色素材的右下角本来就是空的（透明），手柄画在那儿等于画在空气上：鼠标一挪过去就被穿透到桌面/后面的程序，窗口收到 `MouseLeave` 就把手柄收起来了。表现就是**"鼠标移过去半截，手柄没了"**。

所以手柄做了两件事：

1. 底下铺一层 `#01000000`（alpha=1）：**肉眼完全看不见，但已经不算全透明**，Windows 就会把它算作可命中。这样手柄压在任何透明美术上都能稳稳点到。
2. 命中区 30x30、箭头只画在右下角 → 又大又好点，看着仍然贴在角上。
3. 显隐切的是里面那层 `GripArt`，**不能用 `ResizeGrip.Opacity` 隐藏**——`Opacity=0` 会让整块像素重新变成全透明，手柄一旦藏起来就再也摸不到、也就再也不会显形（死循环）。
4. 鼠标离开后**延迟 300ms 再确认**才收：立绘的空隙（发丝、手臂之间的空当）都是穿透的，鼠标从她身上挪向手柄时中间会穿过这些空隙，立刻收就会闪。

同理，她身上任何**透明的地方点下去都会穿透**（这是特性不是 bug：不挡桌面操作）。想按住她拖动，请按在实心处。

### 为什么拖动缩放不能用 `DragDelta`（踩过的坑）

`Thumb` 的 `DragDelta.HorizontalChange / VerticalChange` 是**相对手柄当前位置**算的增量。而手柄钉在窗口**右下角**——窗口一变大，手柄自己就往右下跑，**鼠标一动不动也会产生位移量**，而且方向正好相反。

于是：缩放 → 窗口变大 → 手柄右移 → 增量变负 → 跳回最小值 → 窗口变小 → 手柄回移 → 增量又变正……

症状就是**拖的时候大小疯狂闪烁**，每次拖都掉到最小（0.2 的钳位地板）。日志长这样，一眼能认出来：

```
应用缩放：0.26 → 63x89
应用缩放：0.20 → 48x68     ← 掉到地板
应用缩放：0.33 → 79x112
应用缩放：0.20 → 48x68     ← 又掉
应用缩放：0.35 → 83x118
应用缩放：0.20 → 48x68
```

**正确做法**：按下时记一次**鼠标的屏幕坐标**当原点，之后每次都用"当前屏幕坐标 − 原点"算位移，与窗口的位置和大小彻底无关（`CursorScreenPoint()` 里做了设备像素 → 逻辑像素的换算，高 DPI 也对）。

> 💡 顺带一提：缩放按"相对变化更大的那个轴"算。所以斜着拖 40px，宽是 +40、高会按比例多涨一点（不会正好等于 40）——这是"保持比例"的必然结果，不是 bug。

### 我调过的大小，重开会不会变回去？——不会

**本机自己定过的值永远是本机的**：

| 值的来源 | 谁说了算 |
|---|---|
| 你在这台机器上**拖出来的尺寸**、在**托盘按过的开关**（锁定 / 游戏模式防误触 / 边缘吸附） | **本机**（存在 `C:\Users\Administrator\.jingjing-pet\pet.json`） |
| 后台面板里存的那几个值 | 只在**你这次真的改了它**时才下发覆盖 |

以前的毛病是：面板那份配置**每次开机都会被套用一遍**，而它存的是"你上次点保存时的旧值"，
于是本机拖好的尺寸开机就被冲回默认——表现就是"我调过的大小，重开又变回默认了"。
现在只有**面板里的值真的变了**才让路，其余一律以本机为准（开机日志会写明：`套用面板配置 vN：覆盖本机的字段 = 无（本机值为准）`）。

所以面板里那个「缩放」框更像一条**命令**而不是"当前值"：你改了它立刻生效，但之后你自己拖的大小不会再被它带回去。

## 她说话时：逐字冒字 + 嘴一直动 + 收尾一个表情

气泡里的字不再"啪"一下全出来，而是按 `bubble.typeSpeed`（字/秒，默认 28）一个个冒。几个要点：

- **出完字才开始算停留时长**（`m + 字数 × n`）——不然长句会被提前收走。
- 逐字期间 **talk 一直循环**（嘴不停动）；字出完 → 播这句话的**情绪动作** → 之后自己回 idle。
- 她一次回好几条时，**下一句会等上一句说完再上**，不会把上一句的字掐断。
- 太短的句子（"……"这种，出字不到 0.3 秒）不启动循环，免得只是抽一下嘴角。
- 点一下气泡 = 立刻收起；逐字到一半被点掉也算"这句说完了"，连播不会卡住。

### 情绪怎么定（`Pet/EmotionRules.cs`）

两步，都不需要她配合：

1. **显式标记 `[动作名]`**——句子里写 `[happy]` 就会被认出来，并且**从显示的文字里剔掉**。
   只认"当前皮肤真的加载了"的动作名，所以 `[1]`、`[备注]` 这类方括号原样保留，不会误删。
2. **关键词规则**——从她说的话里找。她本来就习惯用括号描述动作（"（开心地晃了晃辫子）"），直接命中。
   默认表在 `EmotionRules.cs`；想自己加就在 pet.json 里写 `emotions`（键 = 动作名，值 = 关键词数组），
   例：`"emotions": { "happy": ["开心", "嘿嘿"], "sad": ["难过", "呜"] }`。

**皮肤里没有那个动作就什么都不播**（所以只有 idle/talk/happy 时，`sad` 之类的规则会静静待着，不报错、不硬凑）。
关键词前面跟"不 / 没 / 别"会当成否定跳过——"不开心"不会播 happy。

面板「桌面精灵 → 精灵外观与行为 → 气泡」里能调**逐字速度**（填 0 = 关掉逐字，整段直接显示）。

> 💡 想让她主动用标记，只要在**宠物那一侧**的提示词里告诉她"句尾可以加 `[happy]`"就行。
> ⚠️ 但别加进全局人设——那个标记在 QQ 聊天里不会被剥掉，会当正文发出去。

## 动作素材：PNG 序列，或者直接给一张 GIF

`pet.json` 的 `actions.<动作>.frames` 里可以写 **PNG 序列**，也可以直接写**一张 GIF**：

```json
"actions": {
  "idle": { "frames": [ "idle.gif" ],                 "fps": 4 },
  "talk": { "frames": [ "talk/1.png", "talk/2.png" ], "fps": 5.5 }
}
```

- **GIF 会被拆成它自己的每一帧**，而且**按 GIF 里写好的逐帧延时播**——你导出的 GIF 该多快就多快，不用去猜 `fps`。
- `fps` 只对"没有自带延时"的图（PNG 序列）生效。两者可以混在一个动作里。
- 为什么不能把 GIF 直接丢给 `Image`：**WPF 读 GIF 只显示第一帧，动画是死的**，只能自己拆（见 `Pet/FrameLoader.cs`。
  顺带一提，GIF 里延时写 0 或 1 的帧会被当作 100ms——那是编码器"没填"的意思，浏览器也这么处理，不然会闪到看不见）。

想直接看效果：仓库里带了一套演示素材 **`assets/gif-demo/`**（由 `_make_demo_gif.py` 生成，三帧延时 150/250/400ms）。
把配置的 `assetDir` 改成 `assets/gif-demo`、`actions` 的帧改成 `idle.gif` / `talk.gif` 就能看到 GIF 在她身上跑。

日志会告诉你它读到了什么、节奏对不对（帧计时只打开头 8 帧，不会刷屏）：

```
  idle：idle.gif 拆出 3 帧（GIF，用自带逐帧延时）
播放动作：idle（3 帧 @ 1.2fps × 1，其中 3 帧用 GIF 自带延时）
  帧计时 idle[1]：距上一帧 144ms     ← 对照 GIF 里写的 150ms
```

## 气泡停多久（长文会自动多留一会儿）

> 🔁 **重启不会再复读。** 后端的主动消息队列会保留 5 分钟，而桌面端以前开机时游标从 0 开始，
> 等于说"我一条都没看过"→ 把队列里的历史全取回来重播，于是每次重启她都要把上次说过的话再说一遍。
> 现在**首次轮询只对齐游标、不补播**：开机后她只会说**新**消息。她不在线那段时间，
> 后端本来就改走 QQ 找你了，所以不会漏。
> 同理，开机第一次套用后台配置也不再冒那句「……换好了，这样看着还行吧？」（那是"你改了外形"的回应，不是开机问候）。

停留时长按公式算：**`m + 字数 × n` 秒**（`pet.json` 的 `bubble.baseSeconds` / `bubble.secondsPerChar`，也能在后台面板「桌面精灵 → 精灵外观与行为」里改）。

| 字数 | 5 | 14 | 20 | 40 | 60 | 100 | 200 |
|---|---|---|---|---|---|---|---|
| 默认 m=4、n=0.25 | 5.3s | 7.5s | 9s | 14s | 19s | 29s | 54s |

- `baseSeconds ≤ 0` = **不自动消失**，点一下才关
- `maxSeconds` = 封顶（0 = 不限）——怕超长文本把气泡钉在屏幕上就设它，比如 30
- 图片气泡另有一个 12 秒保底（图没字数，得给够看的时间）
- 每次显示都会在日志里留一行：`气泡停留 7.5 秒 = 保底 4s + 14 字 × 0.25s/字`，想核实就直接看日志

## 气泡摆哪儿（贴边也不会被截）

气泡**默认摆在她头顶**；头顶放不下（她贴着屏幕顶边）就**自动翻到她脚下方**，尾巴跟着换边、并对准她的中心。

- 边界按**她所在那块屏的工作区**算（不含任务栏）——多显示器/任务栏下不会被截掉半截
- `SizeToContent` 首帧尺寸量不准时会在布局落定后再正一次（中文换行、图片刚解码时容易偏）
- 每次首次定位/翻边都会在日志里留一行，例如：
  `气泡翻边：头顶放不下 → 翻到她脚下方（尾巴朝上）；工作区=(0,0,2560x1392) 气泡=245x79 落点=(308,356)`

## 换皮肤（不用改代码）

1. 在 `src/DesktopPet/assets/` 下放一套新素材（目录结构参照 `placeholder/`）
2. 改 `src/DesktopPet/pet.json` 里的 `assetDir` 指向新目录
3. 重新构建（或用已发布版本直接改输出目录的 pet.json，重启即生效）

`pet.json` 能配的东西：缩放、是否置顶、呼吸动画、动作帧与帧率、气泡的颜色/字体/圆角/最大宽度/自动消失时间、后端、吸附。

素材要求：**透明背景 PNG**（`.png`），同一动作的帧尺寸一致（否则会抖）；`tray.ico` 可选（没有就用系统图标）。

## 日志

`%USERPROFILE%\.jingjing-pet\pet.log`（右键菜单/托盘都能直接打开）
启动步骤、动作切换、吸附结果、后端往返全在这里——GUI 程序没控制台，出问题只能靠它。

## 已知坑（踩过的，别再踩）

- `UseWindowsForms=true` 会注入 `global using System.Windows.Forms / System.Drawing`，与 WPF 的 `Application`/`Brush`/`MenuItem` 撞名 → csproj 里已把这两个全局 using 移除，需要时各自显式 using。
- WPF 项目的隐式 using **不含 `System.IO`** → csproj 里补了 `<Using Include="System.IO" />`。
- **`pet.json` 必须设成 Content 复制到输出**，否则运行目录里没有配置 → 动作列表为空、窗口一片透明（这个坑已经在日志里露过脸）。
- **`Window.Left/Top` 不是依赖属性**，没法用 `DoubleAnimation`——吸附动画得用 `DispatcherTimer` 自己走（见 `MainWindow.AnimateTo`）。
- `Screen.WorkingArea` 是**物理像素**，WPF 的 Left/Top 是 **DIP**：高 DPI 下必须换算，否则吸错位置。
- 从命令行/脚本 `Start-Process` 启的 GUI 会被沙箱连坐回收；后台任务方式启动才能活下来。
